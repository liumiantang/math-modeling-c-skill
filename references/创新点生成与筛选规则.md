# 创新点生成与筛选规则

## 核心原则

创新不是增加算法名词，而是解决题目中一个普通基线无法处理、且数据允许验证的具体矛盾。每个创新点必须能回答：

1. 题目中的特殊矛盾是什么？
2. 基线模型为什么处理不好？
3. 新机制如何进入变量、目标函数、约束或验证环节？
4. MATLAB 如何检验它确实带来价值？

## 五类可迁移创新来源

| 来源 | 常见矛盾 | 可形成的模型增强 | 必须验证 |
|---|---|---|---|
| 时序机制 | 趋势、周期、滞后、缺货导致观测值偏低 | 滚动预测、状态转移、缺货修正 | 时间外推和决策损失 |
| 资源冲突 | 容量、库存、覆盖率、成本互相挤压 | 多目标、词典序、惩罚或分层约束 | 可行性和权衡曲线 |
| 不确定性 | 需求、价格、产量、损耗波动 | 情景、区间、CVaR、预算鲁棒 | 最坏情景和方案稳定性 |
| 数据限制 | 标签单一、主体重复、缺失、替代信息不足 | 主体聚合、分层验证、探索性风险排序 | 泄漏审计和结论降级 |
| 全局性/离散性 | 整数、组合、任意混种、非凸 | 上下界、分支定界、候选列池、局部搜索对照 | 最优性边界和时间限制 |

## 创新点筛选表

为每个候选创新打 0～2 分：0=没有，1=部分，2=明确。

| 候选创新 | 机制匹配 | 数据支持 | 可实现 | 可验证 | 可解释 | 总分 | 结论 |
|---|---:|---:|---:|---:|---:|---:|---|
|  |  |  |  |  |  |  |  |
|  |  |  |  |  |  |  |  |
|  |  |  |  |  |  |  |  |

总分低于 7，或“数据支持”低于 1，不作为主创新；最多作为讨论中的待改进方向。总分高但无法独立验证，也不能写成已证实的效果。

## 禁止的伪创新

- 只把线性规划换成遗传算法，却没有新的约束、机制或验证；
- 只增加神经网络层数，却没有证明复杂模型改善了留出期决策；
- 只把相关性写成替代关系或因果关系；
- 只挑一组有利参数展示敏感性；
- 把有限情景下的最优解写成分布鲁棒或全局最优；
- 把 Visio 图的复杂程度当成模型创新。

## 论文写法

创新点应写成“针对 X 矛盾，我们在 Y 位置引入 Z 机制，并通过 A、B、C 验证；结果显示……”。如果结果没有显著改善，诚实写成“建模尝试”或“解释性扩展”，不要包装成核心贡献。
