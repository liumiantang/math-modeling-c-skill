
# 论文一致性审计

在生成 Markdown、Word 或 PDF 前读取。它针对“方法已经改了，但正文仍是旧结论”的问题。

## A. 内容层

- [ ] 摘要、问题分析、模型、结果、敏感性、局限性和结论的章节编号连续且不重复。
- [ ] 每一问都直接回答题目要求，不能只写方法背景。
- [ ] 每个公式中的符号都在符号表出现，变量有单位，约束与代码一致。
- [ ] 结果区分数据事实、模型输出、解释推断和建议。
- [ ] 相关性没有写成替代、因果或工艺证明；预测没有写成机制证明。
- [ ] “最优”“鲁棒”“全局最优”“显著”“稳定”等强词都有对应证据和范围。
- [ ] 缺失门控、Bootstrap 抽样单位、交叉验证层级和敏感性情景在方法与结果中一致。

## B. 数字层

- [ ] 摘要数字来自同一份 MATLAB 结果快照。
- [ ] 表格、图注、正文和附录的样本数、均值、区间、指标、最优值和参数一致。
- [ ] 所有数字都能定位到 CSV/MAT 的字段、脚本和运行日志。
- [ ] 四舍五入只在展示层处理，计算层保留原始精度。
- [ ] 图中的数值标签、坐标轴单位和正文引用与结果文件一致。
- [ ] 修改文本使用章节范围定位；避免对“结果”“模型”“结论”等模糊词做全局替换。
- [ ] 修改后重新检查摘要是否被误改、脚本清单是否过时、图表编号是否断裂。

## C. 竞赛交付层

- [ ] 明确这是原始参赛稿、赛后复现稿还是改进研究稿。
- [ ] 若是正式参赛版，按当年规则检查首页、匿名要求、目录、页数、字体、公式和图表。
- [ ] 删除身份信息、工具痕迹和不符合当年时间线的内容，除非题目或赛规明确允许。
- [ ] 附录给出足够的算法流程和关键代码说明，但不把不可读的代码堆成正文。
- [ ] 最终 Word/PDF 已渲染检查，确认分页、表格、公式、图题和引用没有溢出或空白页。

## D. 失败即停止

以下任一项失败，交付状态不能写为“可直接提交”：
- 关键数字无法追溯；
- 公式或约束与代码不一致；
- 主分析依赖极端插补但没有敏感性说明；
- Bootstrap 单位前后矛盾；
- 求解器结果未独立解码；
- 论文把条件性预测、情景最优写成真实恢复或全局最优；
- 生成文档后没有视觉 QA。
