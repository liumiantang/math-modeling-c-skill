
# 验证与交付协议

本文件只在正式训练、复现或参赛论文交付时读取。它把“结果出来了”变成可以复核的证据链。

## 1. 每问的结果护照字段

建议保存为 model_passport.md 或同结构表格：

| 字段 | 必填内容 |
|---|---|
| 数据版本 | 原始文件路径、读取时间、表名、行列数、独立主体数、清洗版本 |
| 估计对象 | 要预测、比较或优化的量；单位；是样本内、留出期、情景还是反事实 |
| 假设 | 题目给定假设与自行假设分开，写出理由和可证伪条件 |
| 参数变量 | 集合、参数、决策变量、随机量、上下界和单位 |
| 目标约束 | 目标函数每一项的业务含义；硬约束、软约束、逻辑约束 |
| 算法运行 | MATLAB 版本、脚本入口、工具箱、求解器选项、随机种子、运行时间 |
| 验证 | 切分单位、滚动窗口、重复次数、嵌套层级、指标和区间 |
| 风险攻击 | 缺失门控、标签置换、去特征、参数扰动、最坏情景、方案一致率 |
| 输出 | 结果 CSV/MAT、图、日志、关键数字和独立重算值 |
| 限制 | 外部验证、因果识别、全局最优证明、样本量和数据口径限制 |
| 状态 | draft、verified、conditionally_verified 或 blocked |

## 2. 预测与分类的最低证据

- 训练、验证、测试顺序必须符合实际信息可得顺序。
- 时间序列使用滚动窗口；有重复主体时按主体切分。
- 预处理在每个训练折内估计。不得先对全体数据插补、标准化、选特征再交叉验证。
- 至少保留简单基线；主模型只有在留出指标、业务损失或稳定性上改进时才升级。
- 分类报告混淆矩阵、平衡准确率、Macro-F1、灵敏度和特异度；不平衡明显时补 PR-AUC 和校准。
- 小样本至少重复多个随机种子；模型选择和性能评估共用数据时使用嵌套交叉验证。
- 预测区间应说明覆盖率、估计方式和是否按主体/器物簇 Bootstrap。

## 3. 组成数据与缺失数据

- 先判断成分总和是否固定；若固定，记录闭合误差并避免直接解释原始相关系数。
- 零值必须区分真实零、低于检测限和未观测；替换规则不能默认为同一件事。
- CLR 只取满秩坐标或说明冗余维度；逆变换后必须检查和为 100%。
- 相关分析优先采用成对可观测数据。对某一组分观测率过低的成分设门槛并排除主结论。
- 插补结果可用于压力测试，但要标记为 sensitivity，不得把插补产生的相关称为实测关联。
- 多重检验校正只控制检验数量带来的假阳性，不能修复错误的缺失机制或选择偏差。

## 4. 优化模型审计

运行后同时记录：
1. 求解器状态、exitflag、运行时间、上下界和最优性间隙；
2. 变量下界/上界、等式和不等式最大残差；
3. 用原始变量独立重算目标、收入、成本、产量、缺货、浪费、库存和罚金；
4. 名义、保守、最坏和敏感性情景的可行性与目标；
5. 多种子或多初值下的目标离散程度和决策一致率。

必须加入自动断言：无合法操作的变量为 0，所有非负变量确实非负，库存/流量守恒成立，销售不超过可用量，罚金与违约量绑定。若优化器目标与独立解码相差超过预设容差，状态只能是 blocked。

## 5. 可复现输出的最小集合

每问至少有：
- 一个正式入口脚本；
- 一个审计表；
- 一个机器可读的主结果表；
- 一个验证摘要表；
- 一个敏感性/最坏情景表；
- 一份结果护照；
- 一份运行日志；
- 论文中引用的图表源文件。

结果表应含 problem_id、question_id、scenario、seed、unit、metric、value、lower、upper、status 等字段或等价信息，避免只有一张手工排版表。

## 6. 不能写成强结论的情形

遇到以下任一情况，应主动降级措辞：
- 只有样本内拟合或单一情景；
- 关键组分或特征缺失率很高；
- 主体内重复没有按主体处理；
- 标签存在冲突或近乎单一；
- 预测优越性没有传递到决策损失；
- 整数或非凸优化只找到一个启发式解；
- 分支定界未结束或只有有限候选列；
- 没有外部验证或反事实识别条件。
